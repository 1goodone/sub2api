# OAuth 预留坑位

在账号的新建/编辑窗口开启「预留坑位」，设置整数秒数（1–3600，默认 60）。开关默认关闭，仅 OAuth 账号生效，配置沿用账号 `extra`：

```json
{"slot_reservation_enabled": true, "slot_reservation_seconds": 60}
```

批量设置：在「账号管理」勾选 OAuth 账号，点击「批量编辑」，先勾选「更新预留坑位设置」，再勾选「预留坑位」并填写秒数，提交即可。取消内层「预留坑位」可批量关闭；不勾选外层更新框会保持原有配置。按筛选结果批量编辑也支持，所选账号必须全部为 OAuth（可跨平台），混有 API Key 或 setup-token 时不显示此项。每次重新打开弹窗默认不更新、关闭、60 秒。

- 成功请求结束后保留账号并发位；用户和 API Key 请求并发正常释放。
- 预留按已认证用户 ID 与会话标识隔离，Redis 仅保存标识的 SHA-256 摘要。优先读取客户端 session/thread 标识，未提供时沿用现有调度会话标识。
- 同会话续聊原子复用空闲预留位，并在结束后重新倒计时。同会话并行请求各自占用实际并发，结束后合并为一个空闲预留位。
- 预留仍计入所有账号容量检查，不绕过分组、模型、账号可用性和权限检查。Live 长连接的现有租约不改变。
- 客户端主动取消、明确的用户输入错误保留坑位；429、认证失败、上游/传输错误、超时、流式失败取消账号的空闲预留。错误之前已开始的其他请求不能在结束后重新生成预留。
- 容量列显示虚线方框和每个空闲坑位的倒计时；活动请求不显示预留倒计时。整页共用秒级时钟。列表接口通过 `reserved_slot_expires_at` 返回 Unix 秒截止时间，`current_concurrency` 包含活动与预留位。
- 关闭配置后不再创建新预留；已存在的预留在续用或原截止时间到达时消失。无需数据库迁移。

## 验证

新增测试覆盖配置校验、默认值、跨用户/会话隔离、并行请求、重复释放、到期回收、长 TTL、进程启动清理、错误代际保护、内部重试、真实转发边界、普通/高级调度优先复用、调度缓存投影和完整/精简列表响应。

前端相关测试 209 项通过；类型检查和新增组件 ESLint 通过。使用真实 Vue 组件完成本地浏览器渲染检查。

后端默认广泛回归中，repository、handler、admin 包通过。service 包的一个既有 SSE 心跳时序断言失败，单独重跑 3 次通过；middleware 的 `TestAPIKeyAuthForwardsUserScopedOpenAIFastPolicyToUpstream` 返回 502，该失败在原始 HEAD 上同样复现。`-tags=unit` 的 service 测试存在重复 helper 和旧函数签名编译错误，也已在原始 HEAD 上复现。未调用真实 OAuth 上游，未做生产负载压测。
