# 审查修复：配额、请求代理与 TOTP 身份互斥

基线：`ebea306f364aefd6931c70310afb354bf5b7a317`。本次承接 v2.21.6 / #892 集成审查的 F1–F4，不包含部署。原 Documents 工作区不修改。

## 修复与验收

| 问题 | 修复 | 验收 |
| --- | --- | --- |
| F1：首条配额拒绝被首响模式视为已输出 | 标准和透传流在没有先前提交事件时允许明确配额拒绝进入原有 failover | 首响开/关、标准/透传、健康备用/全池耗尽；heartbeat、metadata、文本和工具输出边界 |
| F2：嵌套配额错误进入同账号长时间重试 | HTTP/SSE 共用结构化 quota 分类；读取 `response.error` 的 reset；明确 quota 禁止同账号重试 | 两种信封得到相同策略；无 reset 的明确 quota 换号；普通瞬时 429 保持重试；可靠 reset 进入调度冷却 |
| F3：代理池不可用提前写 503 | 推理转发返回账号级 failover，最终由 handler 写一次响应；无换号循环的计数接口保留 503 | Responses/Chat/Messages 的健康备用与耗尽场景；不直连、不使用旧代理、不追加 SSE；BPS/SIWC/计数入口回归 |
| F4：不同账号的同邮箱 TOTP 轮换并发创建 | 配置行锁后取得规范化邮箱的事务级 advisory lock，随后以独立 READ COMMITTED 查询检查未决任务 | 真实 PostgreSQL 屏障并发，手动/自动四种组合均只有一个创建者；大小写/空格、软删除再导入、不同邮箱对照 |

配额和代理失败均不授予新的 `RequestRejected` 重放权限；已提交输出、账号绑定历史与工具结果继续遵守现有恢复约束。代理失败不惩罚账号调度健康度，也不绕过指定出口。TOTP 使用独立 `totp-identity:` 锁命名空间，不与登录任务锁混用。无需新增迁移、配置或依赖。
