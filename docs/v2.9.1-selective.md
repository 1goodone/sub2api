# Selective v2.9.1 integration (2026-09-29)

This is a selective backport onto main `94d34a7b8`, not a full v2.9.1
upgrade. The base VERSION remains 2.8.20; deployed builds identify the
selective patch set separately.

## Included

- Credential lint, 2FA modal navigation, guard recovery, and zero quota
  reset-card thresholds.
- Encrypted credential V2 enrollment for 2FA imports. Initial credentials
  remain memory-only until enrollment; no legacy plaintext persistence.
- Automatic BPS enable/restore and independent BPS/quarantine rules.
- Optional 403 recovery probes (off by default, 60-minute interval).
- Configurable quality probe schedules and defaults. The existing
  30-minute default and saved settings are preserved.
- Optional initial OAuth configuration and concurrency upgrades, both
  off by default. Concurrency advancement is transactional.
- Optional BPS image warning/compaction policy, off by default.
- Credential Operations naming and icon updates without changing the
  existing TokenGuard V2 routes or API contracts.
- Pelican showcase history pagination. Initial and polling requests stay
  bounded instead of reloading the entire history.
- Optional Channel Monitor V2 candy probes and card view. Probes are
  disabled until configured; the existing analytics view remains default.
- Optional OpenAI priority scheduling and Teams fixed-cost recovery. Both
  switches default to disabled and preserve the existing scheduler when off.

Local Worker controls, credential CAS/identity checks, server-specific BPS
transport handling, API key packages, and average TPS display are retained.
The full upstream version bump remains deferred.

## Database compatibility

Migrations `259_quality_bps_coexist.sql` and
`260_channel_monitor_v2_candy.sql` are added. Existing migrations are
unchanged. The candy migration adds probe/result storage only; it does not
enable probes or rewrite account credentials or business settings.
Old instances must be retained only for draining and rollback, not used
to administer newly created dual-scope quality rules.

## Production acceptance gates

Preserve the current environment, configuration, database, volumes, and
Worker. Build an immutable image labeled with the exact main commit.
Start and verify the candidate separately before changing new traffic.

Do not restart the live application or reload a proxy that closes active
WebSockets. Existing streams must continue on the old instance; old image
relay links and frontend chunks must remain accessible. Test routing,
fallback, rollback, and stream preservation before cutover. Keep a protected
configuration/database backup and the old image/instance. New optional
features must remain disabled unless the operator already enabled them.

Health alone is insufficient: verify image commit, public authentication
behavior, frontend assets, configuration equality, Worker health, and
database/Redis health. If these gates cannot be met, do not cut over.
